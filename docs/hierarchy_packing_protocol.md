# Протокол исследовательского сравнения hierarchy packing

Основание: согласованный пользователем план от 26.10.2026. Этот протокол уточняет
предыдущую постановку статьи для одного нового эксперимента: основной endpoint —
EvidenceCoverage@B=1024 для hybrid, основной контраст — hierarchy минус structure.
Ранее просмотренные 118 вопросов с AI-разметкой используются исследовательски.
Независимое подтверждение, семантическая достаточность evidence и научная новизна
этим запуском не устанавливаются. Параметры не выбираются по retrieval-результатам.

## Метод

Контекст — текущий раздел, его непосредственный родитель и соседние подразделы.
Разделы идентифицируются позициями heading-блоков, а не названиями. Стек заголовков
находит ближайшего активного предка меньшего уровня даже при пропусках уровней.
Соседние H2 под одним реальным H1 могут объединяться; разные корневые разделы — нет.
Текст до первого заголовка представляет отдельную область. Общий родитель не
доказывает смысловую зависимость. При смене родителя новая область не наследует overlap.

Жадная упаковка идёт по целым блокам с целью 480 токенов, включая фактический
overlap. Цепочка заголовков связывается со следующим содержательным блоком внутри
разрешённой области. Если эта единица длиннее цели, но помещается в runtime encoder
budget, она сохраняется целиком. Более длинная единица обрабатывается существующим
oversized fallback на её непрерывном canonical span. Самостоятельный заголовок
возможен при структурной границе, отсутствии содержимого или превышении лимита
самим заголовком; такие случаи журналируются. Исходные блоки не изменяются.

Запрошенный overlap новых вариантов — 64. Перенос целых хвостовых блоков и токенный
overlap oversized fallback соответствуют upstream structure-aware; перенос сокращается,
если полный следующий срез не помещается. Fixed остаётся 480/20; исходный structure
использует runtime budget и overlap 64. Абляция выключает только структурные границы.

## Неизменяемые компоненты и измерение качества

Используется закреплённый source snapshot, MarkdownParser, canonical serialization,
enrichment, multi-qa-MiniLM-L6-cos-v1 и прежние BM25/dense/chunk-first RRF. Модель
загружается локально. Runtime budget учитывает специальные токены encoder; фактические
encoder inputs проверяются на отсутствие усечения. Вход поиска — Chunk.text.

Gold spans должны точно совпадать с Document.canonical_text. Метрики evidence:

- Coverage: покрытые canonical-символы всех gold spans / суммарная длина spans;
  перекрытия найденных чанков внутри evidence не считаются дважды.
- EvidenceRecall@5: объединение первых пяти чанков покрывает не менее 0,8 всего gold.
- EvidenceMRR@5: обратный ранг первого чанка в top-5, который один покрывает не менее
  0,8 всего gold; при отсутствии такого чанка — 0.
- B=1024: брать целые чанки в порядке ранга, пропускать непомещающиеся, не усекать;
  повторный overlap оплачивается повторно. Счёт возвращаемых токенов сохраняет прежнюю
  политику без добавления специальных токенов encoder.

DocumentRecall@5 и DocumentMRR@10 считаются после max-pool по документам до отсечения
уникального top-k. BM25/dense используют все рассчитанные кандидаты; hybrid — все
кандидаты прежнего RRF depth=100. Это не меняет evidence-контекст.

Парный кластерный bootstrap использует 10 000 повторов и seed 2026. Кластер — связная
компонента графа вопрос—gold-документ; вопросы, связанные несколькими gold-документами,
объединяются транзитивно. Текущие 118 вопросов соответствуют 118 документным кластерам.
Интервалы описательные, без поправки на множественные сравнения.

## Ограничения представления и стоимости

Комментарии остаются в canonical text и encoder input. Таблицы и код не выделяются
отдельными типами блоков MarkdownParser; обработка заголовков внутри такого текста
не исправляется в данном эксперименте. Частоты фиксируются в representation_audit.json.

Каждый вариант работает в отдельном процессе, CPU threads=4, batch size=32.
Peak RSS измеряется psutil с интервалом 100 мс и включает модель и индекс. Время
однократное, кэши ОС между вариантами не очищаются. Dense matrix nbytes не является
полным размером индекса. Остаточные различия индексируемых токенов публикуются;
параметры ради выравнивания стоимости не подбираются.

## Запуск и артефакты

Из корня рабочего каталога, используя выбранный Python с зависимостями:

```bash
python article/scripts/run_hierarchy_packing.py --smoke --output-dir article/results/runs/hierarchy_smoke_NEW
python article/scripts/run_hierarchy_packing.py --output-dir article/results/runs/hierarchy_full_NEW
```

Каталог результата должен отсутствовать. После preflight изменение конфигурации,
исполняемых исходников или модели останавливает worker. Сырые входы и snapshot
проверяются по хешам. В manifest фиксируются версии, пути, хеши и команда.

`per_question_metrics.parquet` содержит 1416 строк полного запуска; таблица статьи
строится из 12 агрегированных строк `aggregate_metrics.csv`. Полные rankings
сохраняются в Parquet каждого варианта; `chunk_index` — индекс с нуля в его
`chunks.parquet`. `contexts.jsonl` сохраняет фактически выбранные чанки при B1024.
`report.md` и `article_results.md` содержат интерпретацию, определения и ограничения.
