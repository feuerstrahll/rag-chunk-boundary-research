# LLM Context Sufficiency Evaluation

Статус на 27.10.2026: входы подготовлены, LLM-оценивание не выполнено.
Это небольшой дополнительный исследовательский анализ сохранённого hybrid retrieval.
Сегментация, ранжирование и индексы не запускаются и не изменяются.

Используются две раздельные выборки: 118 ранее просмотренных AI-only QA из
`hierarchy_full_20261026_v1` и 75 исходных IBM gold QA (45 train, 30 ранее
просмотренных test). На AI-only выборке fixed имеет параметры 480/20, structure —
510/64. На исходной выборке берётся сохранённое историческое budget-matched
сравнение fixed 241/10 и structure 510/64. Между выборками результаты не
объединяются: различаются происхождение вопросов и operating point fixed.
Исторические незакоммиченные patches неизвестны; повторное выполнение retrieval
и восстановление исторического pipeline здесь не заявляются.

Контексты формируются существующей `select_ranked_context` из
`packing_evaluation.py`: обход сохранённого hybrid ranking по рангу, целые чанки,
пропуск непомещающихся, без усечения и дедупликации overlap. Бюджет — 1024
WordPiece-токена прежнего MiniLM tokenizer, revision
`9c441fc9d77eb051358e49979a385d07a511c3c5`. Текст чанков соединяется двумя
переводами строки; отдельно проверяется бюджет сериализованного текста.
Это единица прежнего EvidenceCoverage, а не 1024 токена нативного tokenizer судьи.
Вопрос и общие инструкции судьи не входят в retrieval budget. Метаданные не добавляются.

Судья получает общий rubric и только JSON с `question` и `context`. Вызовы
перемешаны с seed=2026; request ID непрозрачен. Названия метода, QA-источник,
эталонные ответы, gold spans, coverage и IDs документов судье не передаются.
`mapping.jsonl` хранится отдельно. Один существующий deployed model вызывается
с `temperature=0`, `max_tokens=400`, JSON response format; исходные ответы
сохраняются. Отказ API принимать параметры, усечение или некорректный JSON
останавливают запуск. Параметры автоматически не ослабляются, модели не заменяются.
Нулевая температура не гарантирует воспроизводимость серверного inference;
поэтому сохраняются фактическое имя модели и полный ответ API.

Метки: `sufficient` — возможен полный обоснованный ответ без внешних знаний и
предположений; `partial` — поддерживается только часть ответа; `insufficient` —
контекст не поддерживает содержательный ответ. JSON содержит `sufficiency`,
`reason`, `missing_information`. Генерация самих ответов не проводится.

Sufficiency Rate — доля `sufficient` среди всех вопросов соответствующей
выборки и метода. Анализ требует полного совпадения ID и по одной валидной оценке
на каждый контекст. Пропущенные/ошибочные оценки не считаются `insufficient`.
Основная разность — structure минус fixed на одинаковых вопросах. Описательный
95% percentile bootstrap CI вычисляется существующим
`paired_cluster_bootstrap`: 10 000 повторений, seed=2026, совместная выборка
компонент связности графа gold-документ–вопрос. В каждом повторении сохраняются
пары методов. Результаты исследовательские, без независимого holdout.

На AI-only выборке сохранённая EvidenceCoverage@1024 сверяется с пересчётом на
точно тех же выбранных чанках. Сопоставление с достаточностью — таблица чисел
наблюдений для coverage=0, 0<coverage<1, coverage=1 и трёх меток судьи.
Выделяются все случаи coverage>0 с `partial`/`insufficient`; полное покрытие
отличается от частичного. Для исходных gold QA готовой EvidenceCoverage@1024
на этих исторических контекстах нет; поле остаётся пустым. Coverage@5 не
подменяет Coverage@1024. Новый aligner и дополнительные метрики не вводятся.

После реальных вызовов скрипт выбирает 12 разных вопросов для содержательной
проверки оценок: прежде всего полное coverage с недостаточностью, затем различие
меток методов и нулевое coverage с достаточностью. Проверка должна прочитать
вопрос, полный переданный контекст и обоснование судьи; записать отдельные
`reviewed_label`, `review_reason`, исполнителя и статус. Сырые оценки сохраняются.
Проверка Codex должна называться AI content review, а не человеческой проверкой.
Без выполненной проверки заключение о добавочной информации остаётся предварительным.

Если доступного независимого LLM endpoint с temperature=0 нет, оценки не
имитируются: статус `prepared_not_evaluated`, вызовов и проверенных оценок — 0,
Sufficiency Rate, парная разность и CI отсутствуют. Это ограничение исполнения,
а не нулевой эффект достаточности.
