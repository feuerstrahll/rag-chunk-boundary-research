# Протокол v2: конкретные непрерывные контекстные связки

Новый исследовательский этап от 27.10.2026. Код, параметры и примеры разработки
замораживаются до нового retrieval. V1, его протокол и результаты не исправляются.
Проверяется гипотеза: сохранение фрагмента с контекстом области/назначения может
увеличить полноту возвращаемой информации при том же токенном бюджете.

## Компоненты и единицы упаковки

Общая реализация `ContextAwarePackingChunker` имеет `heading_chains` и `intro_rule`.
При обоих выключенных переключателях вызывается неизменённый v1; тестируется
равенство координат. Основное сравнение: сохранённый hierarchy v1; v2 headings;
v2 headings+intro. У обоих v2 target=480, overlap=64, parent boundaries включены.
Размер 481–510 допускается для одной целой предпочтительной единицы, как у v1.
Обычная упаковка и объединение с предыдущим текстом ограничены target=480.

Структурный детектор хранит ожидающие заголовки. При новом заголовке одноуровневые
и более глубокие ожидающие заголовки завершаются как пустые поддеревья; предки
остаются в ожидании. Первый содержательный блок связывается со всеми ожидающими
заголовками своего поддерева. Каждая связь имеет B=целый первый блок,
A=конкретный заголовок, исходные spans. Пересекающиеся интервалы образуют одну
непрерывную единицу. Пустой дочерний раздел может оказаться внутри интервала
предка, но ему не приписывается текст соседнего поддерева. Пустой корень не
переходит к следующему корню, даже при одинаковом названии.

Комментарий `<!-- ... -->` игнорируется только в детекторном представлении при
проверке содержательности. Канонический текст, промежуточные комментарии,
разделители и их токены целиком остаются в интервале. Изменения парсера нет.

Единицы формируются **до** проверки непосредственного родителя. Переходы внутри
связки разрешены; перед ней сравниваются родитель предыдущего содержимого и
родитель начала связки, после неё — родитель её последнего блока. Разные обычные
регионы не получают overlap. При переполнении единица переносится целиком;
сохраняемый хвост предыдущих целых блоков сокращается до фактического бюджета.

Если структурная единица длиннее runtime encoder budget, сначала сохраняется самый
ранний суффикс от дочернего заголовка до конца B, который помещается в encoder.
Префикс режется прежним token-window fallback с overlap=64. Если подходящего
дочернего заголовка нет, fallback применяется ко всему исходному интервалу. Так
длинный предок не разрушает выполнимую дочернюю связку. Это допустимое разбиение,
а не обещание сохранить невозможную связку. Для каждой связи записаны
точные токены, решение упаковки и фактическое сохранение в индексе. Пустые
поддеревья регистрируются отдельно и не считаются потерей существующего текста.

## Отключаемая эвристика вводной, версия connection_fields_1

Это узкий подтип «пункт требует вводную»: короткое имя поля соединения, у которого
без операции и объекта неизвестно назначение. Направление только **B → A**.
Вводная никогда не получает обратную зависимость на весь перечень.

Правило разработано на документах, упомянутых исходными 45 train QA, по прежним
AI-проверенным примерам. Опорный случай `pilot_025`: `Port number` требует
`To create the connection asset, you need these connection details:` и заголовок
`Create a Watson Query connection`. Вводная сама не называет Watson Query;
заголовок и вводная совместно входят в A. Самодостаточные шаги импорта из
`pilot_004` и утверждение о типах импутации `pilot_008` — отрицательные примеры.
У `pilot_010` не добавляется обратная зависимость вводной на всю таблицу.

Фиксированные признаки:

1. A — paragraph из **одного** предложения формы `To create/configure/set up/connect
   to <object>, you need/must provide/must enter/must specify/provide/enter/specify
   these/the following [connection] details/information/values/settings:`.
   Операция, необходимость ввода и объект должны быть явными. Одного маркера
   `following`, `this setting`, `in this case` недостаточно.
2. Объект — именованное соединение: `a Watson Query connection` и аналогичная
   лексическая форма с собственным именем/технологией с заглавной буквы. Общее
   `the connection asset` разрешается только через единственный активный заголовок
   операции `Create/Configure/Set up/Connect to ... connection`, который одновременно
   является ближайшим заголовком. `new`, `existing`, `your`, `this`, `database` сами
   не являются конкретным именем. При конкурирующих заголовках правило воздерживается.
3. Следующий содержательный блок — list. Область — этот непрерывный ряд list,
   пропуская только comment-only блоки. Любой заголовок либо иной содержательный
   блок закрывает область. Вложенность списков не восстанавливается новым парсером.
4. B полностью совпадает с закрытым перечнем коротких имён: Database name,
   Hostname [or IP address] [of the database], IP address, Port [number], Instance ID,
   Username/User name, User ID, Password, API key, SSL certificate
   [if required by the database server]. Markdown emphasis/списочный маркер и
   конечная точка допускаются. Ссылка, код, инструкция, дополнительное предложение,
   альтернатива/условие вне этой формы, описание собственного объекта — отказ.

Это намеренное воздержание вне одного подтипа, а не классификатор всех смысловых
зависимостей. Не рассчитываются precision/recall по предсказаниям как по gold.
Новые решения сохраняются как `AI_proposal`, без человеческой аттестации.

Каждый предложенный B получает собственный интервал от минимального A до конца B,
включая все промежуточные поля и комментарии. Вписывающиеся пересекающиеся интервалы
объединяются. Невписывающийся длинный интервал отвергается с причиной, не разрушая
короткие допустимые связи. При конфликте объединения предпочтение у структурной
единицы; конфликт явно регистрируется. Нет выборочного вырезания промежуточных полей,
дописанного контекста, новой модели, DP или retrieval-time expansion.

## Сравнимость и заморозка

Корпус IBM watsonxDocsQA: 1144 Markdown-документа, revision и SHA-256 из v1.
Snapshot парсера, canonical text, MiniLM revision, CPU threads=4, batch=32,
BM25 k1=1.5/b=0.75, dense cosine, RRF constant=60/depth=100, tie-breaking и
целочанковая budget packing B=1024 неизменны. Encoder budget разрешается в runtime
и должен совпасть с v1 (510); фактические входные IDs проверяет прежний DenseIndex.
Повторный overlap оплачивается повторно. Никакой генерации ответов нет.

Для одинаковых canonical spans сохраняется тот же chunk_id, что у v1: базовый
хеш параметров v1 служит пространством идентификаторов. Полный хеш конфигурации
v2 отдельно сохранён в provenance и preflight. Это исключает перестановку равных
scores из-за переименования неизменившихся чанков; алгоритм tie-breaking не меняется.

Старый hierarchy используется только после проверки config, входов, model hashes,
snapshot identity, старых source hashes, Python и всех записанных версий пакетов,
целостности файлов завершённого запуска и runtime budget. Иначе запуск останавливается
без подстановки старых результатов. Его затраты помечаются как повторно использованные
измерения v1; времена однократные, cache effects не устраняются.

Все параметры, правила, source hashes, development examples, модель, QA train,
проверенные метки и аудит 132 случаев фиксируются в preflight до retrieval. 118 QA
и их evidence не используются для разработки правила или выбора порогов.
Это уже просмотренная AI-only выборка; новый запуск — продолжение исследования,
не независимое подтверждение. Между вариантами параметры не меняются.

## Оценивание

Основной endpoint: hybrid EvidenceCoverage@B=1024; дополнительные — Coverage@5,
EvidenceRecall@5 при tau=0.8, single-chunk EvidenceMRR@5, DocumentRecall@5 и
DocumentMRR@10 после max-pool по документам. Все определения берутся из v1.
Фактические токены контекста, число/квантили размеров чанков, fallback, overlap,
время сегментации, BM25/dense/query, peak RSS и bytes dense matrix сохраняются.
Парные описательные 95% bootstrap-интервалы: 10000 повторов, seed=2026, связанные
gold-документами кластеры; контрасты headings−v1, headings+intro−headings и total−v1.
Нет поправки на множественность или подтверждающего заявления.

Отдельные показатели поведения:

- **Index preservation**: хотя бы один чанк содержит B и **все** A группы.
- **Retrieved completeness**: объединение выбранных чанков B1024 содержит целиком
  B и все A; A и B могут быть в разных чанках. Показывается также top-5.
  Отдельно знаменатели всех query×group пар и только случаев с целиком найденным B;
  при нулевом знаменателе результат null, не нулевая полнота.
- Структурные связи перечисляются для всего корпуса независимо от v1 diagnostics;
  проверяются исправления известных 132 и новые разрывы относительно полного v1.
  Это проверка алгоритма, не доказательство retrieval-эффекта.
- Смысловые показатели считаются только по семи ранее content-checked AI-группам
  и отдельно по двум новым AI-предложениям разработки (Database name, Instance ID),
  с явным provenance. Непроверенные черновики не становятся gold. Человеческий
  знаменатель равен нулю. Пересечение размеченных документов и 118 QA показывается;
  пустое пересечение не скрывается и не компенсируется новыми запросами.
- Срабатывания правила по корпусу — детекторная статистика без заявленной
  подтверждённой смысловой необходимости. Отказы и невозможные интервалы сохраняются.

Результаты, конфигурация, логи, полные rankings и контексты помещаются только в новый
каталог `article/results/runs/context_full_20261027_v2`. Не использовать resume.
