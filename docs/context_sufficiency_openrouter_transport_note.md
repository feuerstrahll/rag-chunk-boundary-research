# Уточнение транспорта OpenRouter после 23 оценок

Первый запуск получил 23 валидных JSON. Затем API сообщил ограничение нового
аккаунта 20 запросов/минуту и конкретную временную ошибку HTTP 402:
`reason=in_flight_budget_exhausted`, `Retry-After: 120`. Это не интерпретируется
как доказательство отсутствия средств: сам API предлагает повтор после завершения
ожидающих запросов. Баланс/лимиты аккаунта не изменяются.

Продолжение создаёт новый каталог и переносит 23 оценки **без изменений** из
прерванного запуска. Исходные raw JSON, метки и hashes проверяются. Ни один уже
оценённый контекст повторно судье не отправляется. Исторические и завершённые
запуски не возобновляются и не перезаписываются.

Меняется только транспорт: интервал между стартами запросов не менее 3,3 с
(менее 20/мин), соблюдение Retry-After. Помимо 429/5xx допускается повтор HTTP 402
только при точной причине `in_flight_budget_exhausted`; обычная нехватка средств
повторно не запрашивается. Rubric, модель, провайдер, температура, seed, бюджет
выхода и входные контексты сохраняются. Изменение основано на ответах транспорта,
не на метках достаточности. Полные параметры и происхождение переноса фиксируются
в новом `run_config.json`.
