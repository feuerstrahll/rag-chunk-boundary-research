# Контракт исследовательского конвейера Markdown

Статус: инвентаризация существующей воспроизводимой реализации и её границ. Основная исполняемая точка входа — `scripts/run_stage_a_baseline.py`, конфигурация — `configs/baseline.json`. Входной корпус — IBM watsonxDocsQA `md_document`, pinned revision `f7da4b6d8a8c4609c49fda06af3bea29b6ef9be4`; SHA-256 корпуса и QA указаны в конфигурации. Upstream snapshot создаётся `scripts/prepare_baseline_snapshot.py` и копируется в новый run directory. Исторические upstream результаты читаются без изменений.

| Компонент | Вход → выход | Реализация и ограничение |
| --- | --- | --- |
| Представление | Markdown и source URL → `Document`, `Block`, canonical text, `section_path`, `source_anchor` | Snapshot `src/parsers/markdown.py`, модели `src/models/contracts.py`. Блоки и offsets связываются с источником. HTML-комментарии и некоторые таблицы/списки остаются плоскими блоками; это отдельный дефект представления. |
| Сегментация | `Document` и tokenizer budget → `Chunk` с contiguous char span | Snapshot `src/chunking/structure.py`; правила структуры, oversized и overlap находятся в коде. Сравниваемый fixed — snapshot `src/chunking/fixed.py`, выбранная конфигурация `480/20` зафиксирована в upstream `article/results/stage_a/step4_20261018_v2/baseline_selection.json`. Новый механизм границ не реализован. |
| Метаданные и текст индекса | `Chunk` и `DocumentSource` → `ChunkMetadata` и индексируемый текст | Snapshot `src/enrichment/chunks.py` добавляет title/source/anchors как метаданные, не меняя canonical slice. `BM25Index` и `DenseIndex` в `src/retrieval/ranking.py` индексируют **только `chunk.text`**; формат сериализации title/section в embedding-вход для этого baseline отсутствует. Его изменение потребует отдельной конфигурации и контрольного сравнения. |
| Валидация | Canonical text, chunks, encoder → проверенный индекс | `run_stage_a_baseline.py` проверяет `chunk.text == canonical_text[start:end]`; `ranking.py` сверяет фактические tokenizer IDs, special tokens и отсутствие hidden truncation до dense encode. `integrity_statistics` пишет агрегат в `index_statistics.json`. |
| Индекс и поиск | Chunks одного из двух segmenter → BM25, dense, chunk-first RRF | Общий код `ranking.py`; `run_stage_a_baseline.py --segmenter structure|fixed` запускает три метода и сохраняет `retrieval_runs.parquet`. Выбранный fixed `480/20` ограничен тем же encoder budget. Парный текущий retrieval run ещё не выполнен. |
| Оценка и затраты | QA и gold → metrics, run manifest, timing/RSS | `run_stage_a_baseline.py` сохраняет `chunks.parquet`, `retrieval_runs.parquet`, `index_statistics.json`, `execution_cost.json`, `run_manifest.json`. Аудит смысловых зависимостей проводится отдельно по тем же canonical offsets; он не заменяет retrieval и не задаёт популяционную частоту. |

Контрольный запуск создаёт **новый** каталог результата и проверяет локальные хеши, snapshot, модель и train-only режим. Пример вызова и требования к `--snapshot`/`--run-dir` находятся в `scripts/run_stage_a_baseline.py --help`. Не использовать исторический test как новый независимый holdout. Для сравнения нового сегментатора потребуется сделать параметрический выбор chunker в одном runner, сохранив parser, metadata-to-text policy, encoder, BM25/dense/RRF, запросы и оценку фиксированными.

Статус этого документа: компоненты structure и fixed связаны одной исполняемой точкой входа с общим parser/index/retrieval/evaluation кодом. Для нового парного retrieval результата необходимы два запуска в отдельных каталогах по одинаковым train QA и их сопоставление; такие запуски здесь не объявляются выполненными. Исторические dirty patches upstream не восстановлены; точным воспроизведением исторического запуска текущий runner не называется.

Smoke-проверка этой общей точки входа выполнена на тех же двух train QA и том же snapshot: `results/runs/fixed_smoke_20261023_v2` и `results/runs/structure_smoke_20261023_v1`. Получено 15 fixed и 28 structure чанков, `block_char_coverage=1.0` в обеих ветках; manifest фиксирует пределы соответственно 480 и 510 текстовых токенов. Smoke служит проверкой исполняемости и контрактов, а не оценкой сравнительного качества retrieval.
