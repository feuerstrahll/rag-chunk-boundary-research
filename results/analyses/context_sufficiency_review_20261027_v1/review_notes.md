# Содержательная проверка 15 оценок GPT-4o

Исполнитель — Codex. Это AI content review с чтением полного вопроса,
переданного контекста и сырого обоснования судьи; **не человеческая разметка**.
Эталонные ответы в проверке не использовались. Выборка целевая, для диагностики
спорных оценок; её нельзя использовать как случайную оценку частоты ошибок судьи.
Сырые метки сохранены, корректированный Sufficiency Rate не рассчитывается.

Отобраны 15 оценок: широкие gold-вопросы с требованиями дополнительной полноты,
coverage=0 с sufficient, coverage=1 с partial, обе стороны одной пары о model
nuggets и отрицательный контроль. В CSV/JSONL для каждого случая есть request ID,
вопрос, метод, hash полного контекста, исходная метка и обоснование, отдельная
проверочная метка, точная цитата и замечание. Все цитаты проверены как подстроки
фактически переданного контекста.

Три важных наблюдения:

1. **Лишние требования полноты.** Для `train_41/fixed` судья требует инструкцию
   импорта в существующее deployment space, хотя вопрос относится к новому.
   Все три нужных шага есть в тексте. Для `train_19/fixed` он требует kNN и
   Naive Bayes сверх явно перечисленных трёх семейств custom text classification.
   Эти partial не доказывают недостаточность контекста для заданного вопроса.
2. **Полное evidence не гарантирует правильную оценку судьи.** В
   `holdout_auto_095/structure` coverage=1, а GPT-4o ставит partial, требуя подробный
   механизм data poisoning. В контексте есть и определение искажённых обучающих
   данных, и их влияние на malicious pattern и нужный атакующему output.
   Дополнительные exploit-примеры вопросом не запрошены. Это ошибка/завышение
   порога судьи, а не подтверждённый orphan-context failure.
3. **Coverage=0 с sufficient требует проверки субъекта.** В
   `holdout_auto_090/fixed` нужные nominal fields явно указаны в контексте: это
   содержательная информация сверх координатного coverage. Но в
   `holdout_auto_085/fixed` вопрос о `applyselflearningnode.sort`, тогда как
   контекст описывает `sortnode` и `distinctnode`. Перенос Ascending/Descending
   между API-узлами без указанной связи нарушает запрет предположений.

Есть и согласующиеся случаи. В `holdout_auto_101/fixed` прямо сказано
«The model nugget is updated instead of replaced»; в парном structure-контексте
есть переоценка весов, но этого утверждения нет. Поэтому sufficient у fixed и
partial у structure имеют содержательное основание.

Для сохранения Data Refinery flow и отрицательного вопроса о несохранённых
полях prompt template зафиксирована неоднозначность области вопроса/допустимых
выводов. Эти случаи не превращаются в уверенные исправления.

Любые итоговые показатели следует называть **сырым Sufficiency Rate GPT-4o**.
Эта проверка показывает реальные причины ограниченной надёжности судьи;
она не создаёт валидированный человеческий эталон и не позволяет механически
исправить все остальные оценки.
