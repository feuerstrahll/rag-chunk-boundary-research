# V2: сохранение конкретных контекстных связок

Новые измерения исследовательского продолжения от 27.10.2026. 1144 документов, 118 ранее просмотренных AI-only вопросов, 118 документных кластеров. V1 и его результаты сохранены без изменений. Старые значения hierarchy переиспользованы после проверки совместимости протокола, кода, входов, модели и версий пакетов. Оба V2 заново сегментированы, проиндексированы и оценены.

## Основной результат

Основной заранее выбранный показатель — **hybrid EvidenceCoverage при B=1024**. V1: 0.736584; V2 заголовки: 0.736584; V2 заголовки+вводная: 0.736584.

Вклад цепочек: +0.000 п.п., описательный 95% кластерный интервал [+0.000; +0.000] п.п. Дополнительный вклад вводной: +0.000 п.п., [+0.000; +0.000] п.п.

Интервал структурного компонента включает ноль: направленный выигрыш retrieval этим сравнением не установлен.

## Правила и отличие от v1

V1 сначала делил документ по непосредственному родителю, поэтому родительский заголовок мог остаться отдельно от первого текста дочернего раздела. V2 сначала накапливает ещё не получившие текста заголовки, связывает их с первым содержательным блоком своего поддерева и упаковывает весь непрерывный интервал. После первого содержательного блока действует обычная упаковка с родительскими ограничениями. Пустые поддеревья истекают на следующем заголовке того же/высшего уровня; пустой корень не получает текст другого корня.

Комментарии игнорируются только при распознавании содержательного блока. Они остаются в canonical text, чанке и токенном бюджете. Target=480, encoder text budget=510, overlap=64. Одна предпочтительная единица может занимать 481–510 токенов. При невозможном бюджете сохраняется самый ранний вписывающийся дочерний суффикс; остальной интервал режется прежним token fallback. Все нарушения регистрируются, токены не удаляются.

Отключаемая эвристика `connection_fields_1` проверяет только короткие имена полей соединения. A должен явно называть операцию, необходимость ввода и объект либо однозначно получать именованный объект из ближайшего заголовка операции. B должен целиком совпасть с закрытым перечнем вроде Port number, Database name, Instance ID. Область действия — непрерывный ряд list после A, прерываемый заголовком или другим содержательным блоком. Одиночные following/this setting/in this case, самодостаточная инструкция, ссылка и неоднозначный объект не проходят правило. Направление только B → A; обратной зависимости на весь список нет.

Полные признаки, отказы, конфликтные интервалы и fallback описаны в `docs/context_packing_v2_protocol.md`; параметры и хеши зафиксированы в frozen_config/preflight до retrieval. Правило построено на исходных train-документах и не менялось по 118 вопросам. Парсер, MiniLM, BM25/dense/RRF и budget packing прежние; одинаковые spans сохраняют прежние chunk_id, чтобы не менять tie-breaking из-за переименования.

## Вклад компонентов и ограничения

Структурный компонент исправил 132/132 известных случаев, новых выполнимых разрывов относительно v1: 0. Это завершённый инженерный результат независимо от направления поисковой метрики.

Для Hierarchy v1 → V2: заголовки совпали все координаты в 1111/1144 документах.

Для V2: заголовки → V2: заголовки + вводная совпали все координаты в 1144/1144 документах.

У эвристики вводной не возникло дополнительного изменения границ: вписывающиеся предложенные связки уже сохранял структурный v2, а длинный интервал оставлен с зарегистрированной причиной отказа. Координаты и chunk_id обоих v2 совпадают во всём корпусе. Вывод ограничен этим правилом и рабочей точкой; из него не следует бесполезность содержательного контекста вообще.

Для отключаемой вводной измеренная дополнительная разность основной метрики составляет +0.000 п.п. Направленный выигрыш не установлен: описательный интервал включает ноль.

Малое число AI-примеров, отсутствие человеческой проверки, узкий лексический охват и прежнее знакомство с 118 QA ограничивают содержательный вывод. Сохранность связки в индексе не тождественна её нахождению и не доказывает полноту ответа.
