# Парный аудит зависимостей: предварительный результат

Проверка десяти заранее выбранных случаев выполнена по canonical тексту и исходному Markdown; решения и минимальные A приведены в `../dependency_annotation_json_20261022_v2/four_case_review_20261022.md`. Четыре прежних разрыва (`031`, `032`, `033`, `047`) сняты как ошибки интерпретации. В `005`, `014`, `025` зависимость подтверждена содержательно. Остальные три записи (`001`, `008`, `039`) отрицательные.

Парный расчёт `paired.json` использует те же B/A spans, выбранный в Step 4 baseline `fixed_m480_o20` и фактические structure-aware чанки. Для каждой положительной записи требуется один чанк, содержащий B и **все** необходимые A. Fixed-окна построены локальным pinned tokenizer по алгоритму `retokenized-v2` с проверкой 480-токенного предела. Входные SHA-256 записаны в JSON.

| Категория | Число из 12 текущих положительных записей | ID |
| --- | ---: | --- |
| Оба сохраняют | 9 | `005`, `011`, `014`, `020`, `025`, `026`, `035`, `049`, `050` |
| Только structure-aware сохраняет | 3 | `010`, `038`, `040` |
| Оба разрывают | 0 | — |
| Только fixed сохраняет | 0 | — |

Все три различающих случая (`010`, `038`, `040`) остаются черновыми метками. `010` и `038` ссылаются из вводной фразы на последующий перечень; здесь ещё требуется проверить, необходим ли весь список для понимания вводной, как это уже было сделано для `047`. В `040` нужно проверить минимальный источник референта `this tutorial`. Среди трёх положительных случаев из содержательно проверенной десятки оба baseline сохраняют зависимость. Следовательно, различие 3/12 пока является кандидатом для проверки текста, а не установленным преимуществом метода. Чанк-сохранение не измеряет retrieval.

Отдельный диагностический отбор зафиксирован в `../dependency_boundary_diagnostic_20261022_v1/selection.json` **до** проверки содержания. Из 79 фактических межблочных концов и 9 концов внутри блока выбраны соответственно 8 и 4 с seed `20261022`; полный текст для проверки без координат границ находится в `blind_review_packet.json` той же папки. Это целенаправленная выборка из документов пилота; по ней нельзя оценивать распространённость проблемы в корпусе. Содержательные решения по этим 12 новым случаям пока не внесены.

Семь `not_applicable` (`006`, `009`, `012`, `018`, `024`, `028`, `030`) относятся к служебным HTML-комментариям, сохранённым как отдельные paragraph и присутствующим в исходном Markdown. Они не являются установленной потерей текста или ошибкой границ; вопрос очистки представления следует вести отдельно от сегментации.

**Решение по этапу 3:** проверенного разрыва structure-aware, устранимого локальной границей, пока нет. Оснований вводить функцию стоимости или DP сейчас нет. Следующий предметный шаг — проверить три различающих черновых зависимости и заполнить зафиксированный диагностический пакет; при подтверждении `structure-only` проверить влияние на retrieval отдельно.
